### Failures

- ID: ENV-01
- Reproduction steps: On a clean checkout of `main` at `7bc5d78`, run `npm ci` then `npm run verify`.
- Expected: Format, lint, strict typecheck, unit tests, and production build all pass.
- Actual: The chained command stops at the first step — `prettier . --check` reports `BUILD_PLAN.md` fails formatting ("Code style issues found... Run Prettier with --write to fix"), and `npm run verify` exits with code 1 before lint/typecheck/test/build ever run. Each of those later steps passes when run individually (`npm run lint`, `npm run typecheck`, `npm run test`, `npm run build` all succeed), so the fix is isolated to `BUILD_PLAN.md`'s Markdown table formatting (or adding it to `.prettierignore` if it's intentionally hand-formatted).
- Evidence: `npm run verify` output, full log captured; `npx prettier BUILD_PLAN.md --check` reproduces the same warning in isolation. `.prettierignore` does not exclude `BUILD_PLAN.md`.

- ID: SHELL-08 (tool label truncation)
- Reproduction steps: Load the shell at any of the three required viewports. Look at the second entry in the left tool rail.
- Expected: All ten tool labels ("Move", "Marquee", "Lasso", "Select", "Brush", "Shape", "Eraser", "Crop", "Picker", "Hand") remain legible text per SHELL-08 ("Text remains legible").
- Actual: `.tool-name` (`src/styles/shell.css:203-209`) is a fixed-width, `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` column inside a 112px-wide, non-responsive tool rail. "MARQUEE" (7 characters) overflows this column at 9px font size and renders as "MARQU…" at every tested viewport and DPR. The DOM text content and the button's `aria-label` are both correct/full ("MARQUEE tool, shortcut M") — only the rendered visible label is clipped, and only for this one tool (the other nine all fit).
- Evidence: `test-evidence/browser-test-2026-08-17/SHELL-08_tool-label-truncation_1440x900_chromium.png` (zoomed crop of the tool rail) and `SHELL-08_1440x900_dpr2_chromium.png` (full shell at 2x DPR, same truncation visible).

- ID: SHELL-08 (command-bar button height)
- Reproduction steps: Load the shell at any viewport. Inspect the `OPEN`, `EXPORT`, `UNDO`, and `NEW` buttons in the top command bar.
- Expected: "Controls remain at least 32 px high where applicable."
- Actual: `.command-button` (`src/styles/shell.css:115-116`) sets `min-height: 30px`, overriding the base `.ui-button` rule's `min-height: 32px` (`shell.css:82-83`). Measured `getBoundingClientRect().height` for all four command-bar buttons is 30px, 2px under the required minimum. All ten tool-rail buttons (36px) and all four inspector tabs (40px) meet or exceed 32px.
- Evidence: Scripted `getBoundingClientRect()` dump: `[{"cls":"ui-button","height":30}, {"cls":"ui-button","height":30}, {"cls":"ui-button","height":30}, {"cls":"ui-button","height":30}]` for the four `.command-button` elements, versus 36px/40px for tool/tab buttons in the same pass.

- ID: A11Y-01 / A11Y-02
- Reproduction steps: Run an axe-core 4.13.0 audit (`axe.run(document, { runOnly: wcag2a/wcag2aa/wcag21a/wcag21aa/best-practice })`) against the production preview `/` and the dev `/__gallery` page.
- Expected: Zero serious or critical violations on both pages.
- Actual: Both pages report one `color-contrast` violation with `impact: "serious"`. The design token `--hazard: #e61919` (`src/styles/tokens.css:11`) is reused as small (9–11px) text color against the dark surface tokens and fails WCAG AA's 4.5:1 minimum in every case axe measured:
  - `.brand-mark` ("LE" logo box) on `--surface-1`: 4.03:1
  - `.eyebrow` text (e.g. "NO DOCUMENT LOADED", "DEV ONLY / __GALLERY") on `--surface-1`/`--surface-0`: 4.03:1–4.25:1
  - `.panel-count` ("00" inspector counter) on `--surface-1`: 4.03:1
  - `.panel-empty > span:nth-child(2)` (empty-panel copy) on `--surface-1`: 3.14:1
  - `.gallery-label` (gallery section labels): 4.03:1
  - `.numeric-suffix` / `.field-value` (gallery unit suffix and live value readout): 3.32:1 / 4.03:1
  - `.ui-button-accent` (white `--ink` text on `--hazard` background — e.g. the "OPEN DIALOG"/"NEW" buttons): 3.86:1
  All measured ratios are below the required 4.5:1 for normal-size text. This is systemic (one color token, reused across many small-text elements) rather than isolated to one component.
- Evidence: Full axe JSON captured for both pages (violation list, `failureSummary` per node, contrast ratios as quoted above). `UI-06_toast-and-contrast_1440x900_chromium.png` and the `SHELL-01_*` screenshots visually show the affected red text/buttons.
